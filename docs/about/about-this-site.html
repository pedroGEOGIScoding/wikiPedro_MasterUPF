1 Publicar un Sitio Web Quarto en GitHub Pages con GitHub Actions

Esta guía proporciona un recorrido completo para crear y publicar un sitio web Quarto en GitHub Pages utilizando GitHub Actions para el despliegue automatizado.

1.1 Requisitos Previos

Antes de comenzar, asegúrate de tener:

  • Git instalado en tu computadora (Descargar Git)
  • Quarto instalado (Descargar Quarto)
  • Una cuenta de GitHub (Registrarse en GitHub)
  • Un editor de texto o IDE (VS Code, RStudio, etc.)

1.2 Paso 1: Crear tu Sitio Web Quarto

1.2.1 1.1 Inicializar un Nuevo Sitio Web Quarto

Abre tu terminal y ejecuta:

quarto create project website mywebsite
cd mywebsite

Esto crea una estructura básica de sitio web Quarto con:

  • _quarto.yml - Archivo de configuración
  • index.qmd - Página de inicio
  • about.qmd - Página Acerca de
  • styles.css - Estilos personalizados

1.2.2 1.2 Configurar tu Sitio Web

Edita _quarto.yml para personalizar tu sitio. Aquí hay un ejemplo de configuración:

project:
  type: website
  output-dir: _site

website:
  title: "Mi Sitio Web"
  navbar:
    left:
      - href: index.qmd
        text: Inicio
      - about.qmd

format:
  html:
    theme: cosmo
    css: styles.css
    toc: true

Opciones de configuración clave:

  • output-dir: Dónde se guardan los archivos renderizados (por defecto: _site)
  • title: El título de tu sitio web
  • theme: Elige entre temas Bootswatch
  • navbar: Estructura de navegación

1.2.3 1.3 Previsualizar tu Sitio Web Localmente

Prueba tu sitio web localmente antes de publicar:

quarto preview

Esto abre una vista previa en vivo en http://localhost:4200 que se actualiza automáticamente cuando haces cambios.

1.3 Paso 2: Configurar el Repositorio Git

1.3.1 2.1 Inicializar el Repositorio Git

En el directorio de tu proyecto:

git init
git add .
git commit -m "Commit inicial: Sitio web Quarto"

1.3.2 2.2 Crear .gitignore

Crea un archivo .gitignore para excluir archivos innecesarios:

/.quarto/
/_site/
/.Rproj.user/
*.Rproj
.DS_Store

El directorio _site será generado por GitHub Actions, por lo que no lo confirmamos.

1.4 Paso 3: Crear el Repositorio en GitHub

1.4.1 3.1 Crear un Nuevo Repositorio en GitHub

  1. Ve a GitHub e inicia sesión
  2. Haz clic en el icono “+” en la esquina superior derecha
  3. Selecciona “New repository” (Nuevo repositorio)
  4. Ingresa los detalles del repositorio:
    • Repository name (Nombre del repositorio): mywebsite (o tu nombre preferido)
    • Description (Descripción): Descripción opcional
    • Visibility (Visibilidad): Public (Público) (requerido para GitHub Pages gratuito)
    • NO inicialices con README, .gitignore, o licencia
  5. Haz clic en “Create repository” (Crear repositorio)

1.4.2 3.2 Conectar el Repositorio Local a GitHub

Copia los comandos de GitHub (mostrados después de crear el repositorio):

git remote add origin https://github.com/tunombredeusuario/mywebsite.git
git branch -M main
git push -u origin main

Reemplaza tunombredeusuario con tu nombre de usuario real de GitHub.

1.5 Paso 4: Configurar GitHub Pages

1.5.1 4.1 Habilitar GitHub Pages

  1. Ve a tu repositorio en GitHub
  2. Haz clic en la pestaña “Settings” (Configuración)
  3. Desplázate hacia abajo hasta “Pages” en la barra lateral izquierda
  4. En “Source” (Fuente), selecciona “GitHub Actions”

Esto le indica a GitHub que use GitHub Actions para el despliegue en lugar de una rama.

1.6 Paso 5: Crear el Flujo de Trabajo de GitHub Actions

1.6.1 5.1 Crear el Directorio del Flujo de Trabajo

En la raíz de tu proyecto, crea el directorio del flujo de trabajo de GitHub Actions:

mkdir -p .github/workflows

1.6.2 5.2 Crear el Archivo del Flujo de Trabajo

Crea .github/workflows/publish.yml con el siguiente contenido:

name: Publish Quarto Website

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Quarto
        uses: quarto-dev/quarto-actions/setup@v2
        with:
          version: 'release'

      - name: Render Quarto Project
        run: quarto render

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: _site

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

1.6.3 5.3 Entendiendo el Flujo de Trabajo

Componentes del flujo de trabajo:

  • on: push: branches: [main]: Se activa con los pushes a la rama main
  • workflow_dispatch: Permite la activación manual desde la interfaz de GitHub
  • permissions: Permisos requeridos para el despliegue en GitHub Pages
  • concurrency: Previene que múltiples despliegues se ejecuten simultáneamente
  • Trabajo build: Descarga el código, instala Quarto, renderiza el sitio
  • Trabajo deploy: Despliega el sitio renderizado en GitHub Pages

Acciones clave utilizadas:

  • actions/checkout@v4: Descarga tu repositorio
  • quarto-dev/quarto-actions/setup@v2: Instala Quarto
  • actions/upload-pages-artifact@v3: Sube el sitio para el despliegue
  • actions/deploy-pages@v4: Despliega en GitHub Pages

1.7 Paso 6: Desplegar tu Sitio Web

1.7.1 6.1 Confirmar y Subir el Flujo de Trabajo

Añade y confirma el archivo del flujo de trabajo:

git add .github/workflows/publish.yml
git add .gitignore
git commit -m "Añadir flujo de trabajo de GitHub Actions para despliegue"
git push

1.7.2 6.2 Monitorear el Despliegue

  1. Ve a tu repositorio en GitHub
  2. Haz clic en la pestaña “Actions” (Acciones)
  3. Deberías ver tu flujo de trabajo en ejecución
  1. Haz clic en la ejecución del flujo de trabajo para ver los registros detallados
  2. Espera a que los trabajos build y deploy se completen (generalmente 1-3 minutos)

1.7.3 6.3 Acceder a tu Sitio Web Publicado

Una vez que el despliegue tenga éxito, tu sitio web estará disponible en:

https://tunombredeusuario.github.io/mywebsite/

Reemplaza tunombredeusuario con tu nombre de usuario de GitHub y mywebsite con el nombre de tu repositorio.

1.8 Paso 7: Dominio Personalizado (Opcional)

1.8.1 7.1 Configurar Dominio Personalizado

Si tienes un dominio propio, puedes usarlo en lugar de la URL predeterminada de GitHub Pages:

  1. Ve a Settings (Configuración) → Pages en tu repositorio
  2. En “Custom domain” (Dominio personalizado), ingresa tu dominio (ej., www.misitio.com)
  3. Haz clic en “Save” (Guardar)

1.8.2 7.2 Configurar los Ajustes DNS

Añade registros DNS con tu proveedor de dominio:

Para dominio apex (misitio.com):

A     185.199.108.153
A     185.199.109.153
A     185.199.110.153
A     185.199.111.153

Para subdominio (www.misitio.com):

CNAME     tunombredeusuario.github.io

Más detalles: Documentación de dominio personalizado de GitHub Pages

1.9 Paso 8: Actualizar tu Sitio Web

1.9.1 8.1 Hacer Cambios Localmente

Edita cualquier archivo .qmd en tu proyecto:

# Editar archivos
nano index.qmd

# Previsualizar cambios
quarto preview

1.9.2 8.2 Subir los Cambios

Confirma y sube tus cambios:

git add .
git commit -m "Actualizar contenido"
git push

GitHub Actions reconstruirá y redesplegará automáticamente tu sitio web en minutos.

1.10 Solución de Problemas

1.10.1 Problemas Comunes y Soluciones

1.10.1.1 Problema: El flujo de trabajo falla con “Permission denied” (Permiso denegado)

Solución: Asegúrate de que los permisos del flujo de trabajo estén configurados correctamente:

  1. Ve a Settings (Configuración) → Actions (Acciones) → General
  2. En “Workflow permissions” (Permisos del flujo de trabajo), selecciona “Read and write permissions” (Permisos de lectura y escritura)
  3. Marca “Allow GitHub Actions to create and approve pull requests” (Permitir que GitHub Actions cree y apruebe pull requests)
  4. Haz clic en “Save” (Guardar)

1.10.1.2 Problema: Error 404 al acceder al sitio

Solución: Verifica que:

  • La fuente de GitHub Pages esté configurada como “GitHub Actions”
  • El flujo de trabajo se completó exitosamente
  • Estés usando el formato de URL correcto
  • El repositorio sea público (para GitHub Pages gratuito)

1.10.1.3 Problema: Los estilos o imágenes no cargan

Solución: Esto suele ocurrir con rutas base incorrectas. Actualiza _quarto.yml:

website:
  site-url: "https://tunombredeusuario.github.io/mywebsite"
  repo-url: "https://github.com/tunombredeusuario/mywebsite"

1.10.1.4 Problema: El flujo de trabajo no se activa

Solución:

  • Asegúrate de que el archivo del flujo de trabajo esté en el directorio .github/workflows/
  • Verifica que el archivo tenga la extensión .yml o .yaml
  • Confirma que hiciste push a la rama main
  • Intenta activarlo manualmente: Actions (Acciones) → Workflow name (Nombre del flujo) → Run workflow (Ejecutar flujo de trabajo)

1.11 Configuración Avanzada

1.11.1 Usar R o Python

Si tus documentos Quarto usan código R o Python:

1.11.1.1 Para R:

Actualiza .github/workflows/publish.yml para incluir la configuración de R:

- name: Set up R
  uses: r-lib/actions/setup-r@v2

- name: Install R packages
  run: |
    install.packages(c("rmarkdown", "knitr", "tidyverse"))
  shell: Rscript {0}

1.11.1.2 Para Python:

Actualiza .github/workflows/publish.yml para incluir la configuración de Python:

- name: Set up Python
  uses: actions/setup-python@v5
  with:
    python-version: '3.11'

- name: Install Python packages
  run: |
    pip install jupyter matplotlib pandas numpy

1.11.2 Congelar Computaciones

Para computaciones complejas, usa la función freeze de Quarto para evitar re-ejecutar código en cada despliegue:

En _quarto.yml:

execute:
  freeze: auto

Esto almacena en caché los resultados computacionales localmente. Confirma el directorio _freeze/:

git add _freeze/
git commit -m "Añadir computaciones congeladas"
